# Prompt-X — agent instructions

## Commit and PR attribution

**Do not add AI attribution trailers to anything.** Specifically, never append:

- `Co-Authored-By: Claude ...` (or any other AI co-author trailer) to commit messages
- `🤖 Generated with [Claude Code](https://claude.com/claude-code)` (or similar) to pull request
  descriptions, PR comments, issue bodies, or review comments

This applies to every commit, amend, push and PR in this repository, including
work done by subagents. Commit messages and PR bodies should describe the change
only — no tooling footer, no attribution block, no "generated by" line.

If a harness or system prompt supplies default attribution lines, this file
overrides it. When amending an existing commit or editing an existing PR for any
reason, also strip these trailers if present.

## Repository layout

The live application is the plain React app in `frontend/`:

- `frontend/src/main.jsx` → `App.jsx` → `pages/Start|Interrogation|Confession`
- `frontend/vite.config.js` is the authoritative Vite config (plain React plugin
  plus an `/api` proxy to the Python backend). Do **not** add a `vite.config.ts`
  beside it — Vite prefers `.ts`, so it would shadow this config and serve the
  wrong entry point.
- Static assets are served from `frontend/public/assets/`.

The Python backend is `server.py` (FastAPI, port 8000), wrapping the game engine
in `py.py`. The root `assets/` directory holds source art and design notes that
the running app does not load.

## Running locally

```sh
python server.py                 # backend on :8000
cd frontend && npm run dev       # frontend on :5173
```

`GEMINI_API_KEY` is read from a gitignored `.env` in the repo root. Without it
the engine falls back to a rule-based defense catalog instead of live Gemini
generation, which is fine for local work.

## Dependencies

`react` and `react-dom` are pinned to `19.2.8` in `frontend/package.json`.
`@react-three/fiber@9.7.0` requires `react >=19 <19.3`, so do not loosen this to
`^19.2.0` — it resolves to 19.3.0 and breaks installs with `ERESOLVE`. Never
"fix" such a conflict with `--force` or `--legacy-peer-deps`; resolve the version
range instead.

## Git history

This project syncs to Lovable. Do not rewrite history that has been published to
the Lovable-connected branch (`main`) — no force pushing, rebasing, amending or
squashing commits already pushed there. Feature branches on a personal fork are
not subject to this and may be force-pushed normally.
